# 已有 reranker 时，是否再加 dense 混合检索

**建议：有条件采用；目前保留现有管线，只进入离线验证。** 只有融合在相同重排预算下，相对当前生产管线带来有实际价值的最终排序收益，同时满足单查询退步和 CPU 延迟门槛，才值得上线。不能仅凭首阶段平均收益批准，也不能因为已有可靠 reranker 就认定 dense 无价值：它可能补进当前候选集缺失的相关文档，这恰是本地实验要验证的增量。

本服务约有 50,000 篇技术文档，当前 BM25 候选 top-30 交给已验证有效的 cross-encoder；用户阅读前 10 条，CPU 首阶段 p95 预算为 100 ms，重排另有 GPU 预算。[context] 这使最终排序、候选覆盖及严重退步比首阶段均分更有决策价值。

**先把比较对象对齐。** 本文是《The Fusion Tax: A Diagnostic Analysis of When Hybrid Retrieval Hurts》。以下页码均指所给 PDF 的文件页码。论文主分析的可部署参照是 always-dense，另有逐查询选择 BM25 与 dense 较优者的 oracle；后者需要相关性标签，不能直接部署。我们真正要回答的是“BM25＋现有重排器”对“BM25＋dense 融合＋同一重排器”，这不是主分析的比较臂。Table 13 展示 dense、插值及 RRF 的重排结果；作者说包括重排 BM25 在内的完整比较在补充表，但随附材料没有该补充表。因此，目标管线对当前基线的直接增益在所给材料中**未直接测量**。[C4][C5]

**论文支持什么，风险相对谁？**

- 首阶段插值采用 dense 权重 α=0.7。[C3] Table 8（p. 9）相对 always-dense 的平均 nDCG@10 差为 +0.0077～+0.0506；受损查询比例为 8.2%～20.9%，受损时平均损失为 0.044～0.213；受益查询比例为 12.4%～72.0%，受益时平均增益为 0.077～0.221。这说明聚合收益来自受益频率和幅度，而非没有受损者；这些范围不是相对我们的生产基线。[C1]
- 同一表、同一插值方法，相对逐查询 oracle 的受损率为 12.8%～48.0%，净平均差为 −0.0492～−0.0181。它衡量融合距事后较优组件的差距，不能与相对静态 dense 的风险混用，更不能充当相对 BM25＋reranker 的受损率。[C1]
- RRF 相对 always-dense 的净平均差覆盖 −0.0401～+0.1350，受损比例为 15.3%～32.9%，受损时平均损失为 0.096～0.357（Table 8，p. 9）。不能把“无须分数校准”理解成排序安全。[C2] 但它也不是应被排除的方法：在较平衡的 TREC-COVID，首阶段 RRF 为 0.8010，CombMNZ 为 0.8045，高于插值（dense 权重与主实验相同）的 0.7166；NFCorpus 各融合方法接近（Table 5，p. 7）。[C17]
- 风险厌恶评估也有参照和偏好前提：作者报告在 αrisk=5 时，插值相对 always-dense 在七个语料中的六个显著有风险，TREC-COVID 例外（p. 8）。这不是我们用户损失偏好的估计，更不是直接否定生产融合的检验。[C11]

上述首阶段 Table 8 范围均覆盖 SciFact、FiQA、NFCorpus、ArguAna、SciDocs、TREC-COVID、Quora 的完整行集合；按 Interp 和 RRF 分块，未排除负值或端点，也没有跨方法拼出“最优范围”。计算见 table8_interp.json、table8_rrf.json。Table 5 的四舍五入单元格差与 Table 8 的 NFCorpus 净差末位略异；此处首阶段风险收益统一引用 Table 8，不混接不同精度。

**已有 reranker 是决定性限定，不能只读论文摘要。** 作者固定同一 BGE-reranker-v2-m3，对各候选源的 top-30 重排；离线把候选取并集只为复用打分，各臂仍保留相同候选预算，并非把整个并集交给生产重排。Quora 在该实验仅抽取 1,000 个查询（p. 5）。[C4]

Table 13（p. 14）按已显示的小数计算“插值候选重排后 − dense 候选重排后”，完整集合如下；这些是计算值，均为 nDCG@10 绝对差，并非相对当前基线的收益：[C5]

|---|---:|

| FiQA | +0.003 [C19] |
| NFCorpus | +0.010 [C20] |

完整范围下端为 −0.001，[C6] 上端为 +0.018，包含零值；[C7] 最小值与最大值分别见派生账本，逐行差见 table13.json。[C6][C7] 它只说明本配置下两类候选源重排后的观测接近，**不是融合相对当前 BM25＋reranker 的收益上界，也不是其他重排器或更深候选集的上界**。区间跨零也不能证明等效。[C13][C16]

平均接近并不消除个体风险：Table 13 中 FiQA 的插值受损率相对 dense 从 14.7% 升至 15.6%，TREC-COVID 从 14.0% 升至 22.0%。[C5] p. 12 的匹配查询分析进一步说明“净下降”不是原失败全部修复：SciFact 原受损的 30 个查询中修复 27 个，又新增 17 个受损查询。[C8] ArguAna 的 dense 分数从 0.595 降到 0.479，插值从 0.603 降到 0.490，而相对 dense 的受损率却从 19.1% 降至 1.8%；这类下降是重排器覆盖了原排序，并非质量恢复（Table 13）。[C5]

我们的重排器已在本语料稳定改善排序，这是有利的本地证据，但融合可能改变候选分布，仍需在新候选上验证。首阶段相关文档跌出展示截断与跌出重排候选集也不是同一事件：只要还在候选集中，重排可能救回；已被候选截断排除的文档，重排无法凭空补入。论文报告聚合 recall 保持时仍存在个体覆盖损失（p. 8），所以不能仅凭平均 recall 放行。[C15]

**融合方式与权重：给可验证的起点，不给未经测量的生产常数。**

先测本地 BM25 与 dense 的强弱及互补性，并保留“不融合”候选。若 dense 明显占优，优先测试按查询、按检索器分别 min–max 归一化后的分数插值，α 为 dense 权重，初始候选取 0.6、0.7；若两者接近，加入 α=0.5、RRF 和 CombMNZ。[C12] 论文固定插值以各路 top-100 归一化，RRF 用 k=60（p. 5）。[C3][C12] 这些只是搜索起点：若本地 BM25 更强，也应允许更小的 dense 权重；端点 BM25-only 与 dense-only 必须保留。最终按**留出集上的重排后收益与风险**选择，不按首阶段均分直接定权重。

论文跨语料选择权重后，Table 4（p. 7）的插值对 dense 受损率为 LOCO 10.6%～25.0%、语料内 CV 8.2%～26.0%，说明选权重能迁移一些平均效果，却不保证个体安全。[C12] 不建议第一版引入按关键词/自然语言标签切换的逐查询路由；这些标签适合分层诊断，尚无证据能可靠决定是否融合。论文廉价特征路由的留出结果没有胜过静态插值，但仅否定所测分类器与阈值流程，不能推广成“所有路由都无效”（p. 12）。[C14]

实现前要固定去重、缺失文档的分数处理、归一化分母为零及同分排序规则，并核对论文或本地明确规格。所给正文不足以核验全部边界处理；不得仅凭公式声称完全复现。离线保留各路候选 ID、原分数、融合分数与重排分数，以定位是候选丢失还是重排改变。

**成本：我们加的是 dense，不是论文讨论中便宜的新增 BM25。** 最接近目标文档量的 FiQA 例子在 Table 14（p. 14）：约 58k 文档，BGE-small 矩阵 88 MB、BGE-large 236 MB；BM25 中位延迟 2.0 ms，dense 查询编码 6.1 ms、精确 FAISS 搜索 1.3 ms、插值 0.08 ms。[C9] 测量来自 Apple M5、16 GB 统一内存、热缓存、单查询批次；延迟采样通常是 200 个查询（p. 5）。[C10] 这些中位数不能相加后当作本服务 p95，也不能直接推断满足预算。

在约 50,000 篇技术文档的实际切分单位上，需核算 embedding 模型驻留内存、向量矩阵、索引构建与增量更新、CPU 并发争用和故障降级。[context] “篇数”不等于向量数；若按块编码，要报告实际块数。论文使用精确搜索；若更换近似索引，其召回与延迟需要重新测量。并行检索的关键路径仍包括查询编码、检索、融合、排队与通信，不能只计融合耗时。保持重排候选预算不变时，GPU 打分数大体不增，但候选长度变化仍可能改变吞吐；不得顺手扩池并把成本当作不变。dense 超时须快速回退当前管线，纳入尾延迟与质量统计。

**上线前测量与预注册判定。** 以下门槛是本次建议，来自排序退步敏感的业务需求，不是论文已验证的常数；执行前可由评审调整，但调好后冻结，不能看测试结果再改。

- 比较臂：A 为当前 BM25＋现有 reranker；B 为 dense＋同一 reranker；C 为融合＋同一 reranker，同时记录各臂首阶段效果。所有臂固定重排 top-30、展示 top-10，使用相同快照、过滤、去重、重排器和打分设置。[context] C 对 A 是主比较；C 对 B 用于判断“融合”是否真的优于单独 dense。若 B 更好，应评审替换检索器，而非强行采用融合。只有初阶段融合领先而最终不领先，应保留 A。
- 从真实查询流随机抽样，按关键词型、自然语言型、精确标识符/版本号、长查询和业务领域分层。罕见高风险查询可加抽，但总体均值要按生产流量回权。独立抽样单位是用户意图簇；同一用户反复改写、同一会话查询不能当作独立样本。训练选权重、pilot 和最终留出集按意图簇及时间隔离。
- 对所有比较臂最终前 10 条做匿名混合相关性标注；评估候选 recall@30 时补充候选池标注，并对池外遗漏做抽查。标注者看不到来源，明确技术版本适配和答案完整性，分歧复核。没有充分 qrels 时只能称“池内已知相关文档覆盖”，不能声称测得完整召回。[context]
- 输出最终 nDCG@10 配对均值差及区间、受益/受损/持平比例、受损条件平均损失和高分位损失；严重退步定义为 C 相对 A 的单查询 nDCG@10 差低于 −0.05。[context] 同时报相关文档完全消失比例、首阶段和候选覆盖、关键分层结果，保存受损查询个案。按同一查询追踪“已修复、新受损、仍受损”，避免净受损率掩盖转移。
- 先收集约 200 个独立意图簇做 pilot，估计实际 C−A 与 C−B 配对差的方差、相关性和严重退步率，并估算标注一致性。[context] 变异来源包括查询类型、领域、相关性标注、时间漂移和运行负载；质量区间按意图簇重采样并按流量回权，系统延迟另做重复负载测试。权重选择在开发数据或嵌套交叉验证中完成，冻结最终配置后只检验留出集；多候选/多关键分层采用预定的多重比较控制。
- 精度目标：最终平均差的 95% 区间半宽不超过 0.005；样本量以 pilot 对实际比较臂的估计重新规划。[context] 论文 p. 15 的 dense−BM25 标准差并非 C−A 的标准差，不能挪用。[C16] 附 precision_scenario.json 仅举独立等权配对均值的反例：假设标准差 0.20，400 个独立查询的近似半宽为 0.0196，要达到 0.005 半宽需约 6147 个；这不是功效分析、不是实际样本量承诺，也不适用于未经修正的聚类加权样本。[context] 宽区间跨零属于证据不足，不能称无差异；严重退步率的精度需另按二项比例或簇重采样规划，不能用均值半宽替代。
- 建议联合放行门槛：C−A 最终均值点估计至少 +0.01，且 95% 区间下界大于 0；严重退步比例的 95% 上界不超过 5%；每个预定关键分层平均差的 95% 下界不低于 −0.005。[context] C 还应相对 B 有可重复的收益或明确风险优势，否则多维护一路检索器缺乏理由。以 0.005 半宽为设计目标可避免用远宽于目标收益的区间宣称能辨别改进；最终仍以实际区间判断。[context] 样本不足以评估任何关键门槛，则结论为继续测量，不按通过处理。
- 在生产等价 CPU、真实文档切分、目标并发及长查询下测端到端首阶段 p95，要求不超过 100 ms；覆盖冷热缓存、更新期间和 dense 超时场景。[context] 同时测 GPU 重排吞吐、内存和索引更新耗时。离线全门槛通过后才进入小流量对照，记录阅读成功、人工反馈及延迟；出现严重排序退步或预算超限即回退 A。本任务只提出计划，没有执行上线或线上试验。

**证据边界与核查记录。** 所给材料只有正文 PDF，没有论文指向的补充表、原始逐查询运行或我们的评测数据，无法重算显著性、匹配查询置信区间或验证当前系统的净收益。BEIR 跨领域结果也未证明对本服务的技术文档、版本标识、语言分布及文档切分策略成立；关键词型与自然语言型的混合流量不是一个已由本文验证的生产分布。正文对多种编码器及稀疏侧替换的稳健性讨论有参考价值，但不会替代目标语料和目标重排器的验证。重排研究只覆盖所测重排器及候选深度，生产硬件延迟也未获证明（p. 15）。[C13]
