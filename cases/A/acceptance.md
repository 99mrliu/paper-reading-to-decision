# A：预先验收，不提供给运行 Agent

任务和论文沿用 Qoder 原版的现有 BM25+reranker 采纳决策。新版本在上一轮暴露的真实问题上修订，属于开发后的新验证，不能冒称从未见过 A 输入。

核心质量按 0/1 检查下列十项；出现实质错误同时记录具体位置，不靠平均覆盖分掩盖错误。with/without 用同一标准。

1. 给出有条件的可执行决定，说明何时不应采用。
2. 分清 oracle、dense、现有 BM25+reranker 三个参照，说明缺失的直接比较。
3. 解释聚合收益与查询级退步并存，数字、参照和条件准确。
4. 说明融合方式依赖稀疏/稠密平衡及权重验证。
5. 正确解释下游重排的有限恢复与新受害查询，不能声称通用性能上界。
6. 若给重排后跨语料范围，必须覆盖全表端点；所选子集必须说明排除理由。
7. 成本明确硬件、计时统计量、文档规模；不能由中位数推出满足生产 p95。
8. 测量计划区分“估计检索器平衡”与“测现有管线改进”，方差与所比较的差值对应。
9. 样本量/精度论断有计算或合理 pilot 方案，不能声称宽于目标效应的区间足以保证分辨；不把不显著当等效。
10. 关键结论能定位页/表/原句，未知项给具体材料与后续路径。

主要比较：十项任务质量与实质错误数量。次要比较：关键事实的直接引文可核查性、耗时和可取得的 token 用量；账本存在或篇幅更短本身不视作实质增益。基线不强制实现 Skill 的 JSON 格式，不因未提供账本扣质量分。没有独立评阅者计时，不宣称已测评审成本。

计划 A1/A2 两组独立公平配对，统一长度、工具和墙钟预算；首组之后不更改 Skill 或任务。若全部失败或额度耗尽，保留记录并说明，不能补写成功运行。
